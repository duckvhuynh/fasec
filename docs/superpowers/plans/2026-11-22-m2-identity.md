# M2: Identity, enrolment, secure storage (+ pre-M2 hardening) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fasec knows who is who: the owner and authorised users enrol with a guided 5-pose flow, their face templates are stored encrypted (DPAPI) with an Argon2id owner PIN, and each tracked face gets `IdentityState::Known/Stranger` from a voting matcher — with model files loaded only from verified bytes and embeddings kept out of the serialisable report.

**Architecture:** Two hardening tasks first (verified in-memory model loading with an embedded manifest; embeddings moved from `VisionReport` to a separate non-serialisable channel). Then `fasec-platform` gets DPAPI behind a small trait that platform-neutral `fasec-identity` consumes; `fasec-identity` owns the SQLite gallery, PIN, matcher/voter and the enrolment state machine. Finally the pieces are wired into `fasec-replay` (`--gallery`) and two `fasec-ui` examples (`enroll`, names in `live_debug`).

**Tech Stack:** existing workspace (ort 2.0-rc.15, nokhwa, eframe) + `rusqlite` (bundled), `argon2`, `zeroize`, `rand_core`/`getrandom` (salt), `windows` (DPAPI, in `fasec-platform` only).

**Spec:** `docs/SRS.md` §4.2 (FR-ID-001…009), §5.1 (identity state machine), §7.3 (NFR-SEC-001/002/004), §7.4 (NFR-PRIV-001/003), §8.1 (gallery.db schema); `docs/ROADMAP.md` §M2; final review of M0+M1 findings **I2** (model integrity) and **I6** (embeddings in report), recorded in `.superpowers/sdd/2026-11-21-m0-m1-vision-core/final-review-report.md` (gitignored; the relevant text is restated in Tasks 1–2).

## Global Constraints

- Rust edition 2024, `rust-version = "1.92"`, MSVC on Windows. `[lints] workspace = true`; `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` clean before every commit.
- Dependencies via `cargo add -p <crate>`; no `[workspace.dependencies]`.
- Platform-neutral crates (no `windows`/`nokhwa`): `fasec-core`, `fasec-config`, `fasec-vision`, `fasec-identity`, `fasec-policy`, `fasec-models`, `fasec-replay`. DPAPI lives only in `fasec-platform` (Windows-only implementation, a non-Windows stub that returns an error).
- Never commit model weights, face images, recordings or databases. Tests that need models/`.assets`/camera are `#[ignore = "..."]`; implementers run them locally and report.
- Templates and any stored biometric bytes are encrypted at rest through `SecretProtector` (DPAPI in production) — no plaintext template ever reaches disk (FR-ID-004, NFR-SEC-001). No raw enrolment images are stored (FR-ID-005).
- Owner PIN: Argon2id, memory ≥ 19 MiB (19456 KiB), iterations ≥ 2, parallelism 1, 16-byte random salt, stored as a PHC string (NFR-SEC-002). PIN bytes and decrypted templates are zeroised after use (`zeroize`).
- Embeddings never appear in `Serialize` output of `VisionReport` or in `Debug` output of any public type (NFR-PRIV-003, finding I6).
- Model files are hashed and loaded from the same in-memory bytes; the trusted manifest is embedded in the binary (finding I2, NFR-SEC-004).
- Matching defaults (FR-ID-009): cosine, person score = max over that person's templates, accept if `score ≥ 0.363` **and** `score − second_best_person ≥ 0.05`; vote over the last `N = 5` recognitions per track (SRS §3.3).
- Templates are tagged with the recogniser `model_id` (`"sface-2021dec"`); templates with another model id are never compared — the gallery reports "re-enrolment required" (FR-ID-008).
- Fail safe: an identity/storage error must never make a track `Known`. On any gallery/decrypt error the track stays `Pending`/`Stranger`, never owner.
- Errors: `thiserror` in libraries, `anyhow` only in binaries/examples. Logging: `tracing`; never log templates, embeddings, PINs or PHC strings.
- Commits: conventional commits, no attribution lines.

## Review Focus

1. **Corrupted / tampered gallery row (blob edited, wrong length, DPAPI blob from another user)** → load fails for that template with an explicit error; the person is not silently matched with fewer templates in a way that could accept a stranger; no panic. Test in Task 5.
2. **Two people with similar scores (margin < 0.05)** → neither is accepted; the track is `Stranger` (or stays `Pending` until the vote decides), never the closest-but-ambiguous person. Test in Task 6.
3. **A single bad frame among good ones** (one recognition says "stranger" or another person) → the vote keeps the identity stable; it flips only after the configured number of consecutive contrary results. Test in Task 6.
4. **Enrolment with a second face entering the frame, a blurred frame, or a spoof verdict** → that sample is rejected with a reason; progress does not advance; no template from that frame is stored. Test in Task 7.
5. **Model swapped on disk after start-up / during DirectML→CPU fallback** → the session is always built from the bytes that were hashed; a swapped file has no effect on a running pipeline and is rejected at next load. Test in Task 1.
